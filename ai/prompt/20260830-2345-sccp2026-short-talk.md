# SCCP 2026 Short Talk: Predicate-aware Consistency Models

## Role and objective

Act as a database-theory researcher and expert scientific-presenter.  Produce a
five-minute Beamer talk based only on `predicates.tex` and its included material,
through and including Section 6.2.  The talk is for SCCP 2026 workshop attendees
who already understand database consistency; it precedes approximately three
minutes of Q&A.

## Core communication goal

Make the audience leave with one clear message: predicate operations expose both
positive and negative observations, so existing item-only foundations are
insufficient; a predicate-aware axiomatic semantics and dependency-graph
characterization make analysis of `SER` and `SI` principled again.

## Required narrative

1. Start from a minimal, concrete phantom-style example: a query omits a row and
   a concurrent update makes that row qualify.  State why the returned tuples
   alone cannot explain the observation.
2. Introduce the semantic anchor: extend the `(VIS, AR)` framework, and explain
   that an external predicate observation is witnessed per covered item by the
   latest visible writer.  Highlight that an omitted item is still an
   observation.
3. Bridge directly to graph analysis: add `Pred-WR` and observation-sensitive
   `Pred-RW` edges alongside ordinary dependencies.  Explain `changes matches`
   visually rather than deriving definitions line by line.
4. State the two exact results compactly: acyclicity characterizes `SER`; for
   `SI`, every cycle must contain two adjacent anti-dependencies (item or
   predicate).  Make clear that the results are proved against the new semantic
   criterion, not merely asserted by analogy with item-only graphs.
5. Compare the three predicate anti-dependency choices from related work with
   the precise inclusion `Pred-RW^- ⊆ Pred-RW ⊆ Pred-RW^+`; explain the result
   that every relation in this interval preserves the same existential,
   history-level `SER`/`SI` characterization, although graphs and checking cost
   can differ.
6. End with implications, future work (efficient black-box checking and
   robustness analysis), and a single memorable takeaway.

## Slide and design requirements

- Use the supplied `SimplePlus` Beamer template in 16:9.
- Aim for 9--10 principal slides plus references; reserve no more than about
  30--35 seconds for each main idea.
- Favor one visual argument per slide: a compact running example, a relation
  diagram, or a theorem/design-space visual.  Use phrases, formulas, and labels,
  not prose paragraphs.
- Each slide must explicitly lead to the next: question → semantic witness →
  graph abstraction → theorem → design space → consequences.
- Do not re-teach isolation levels or implementation/SMT details.
- Reuse the source paper's notation, commands, packages, formulas, figures, and
  bibliography keys where used.  Copy each reused source figure/table into the
  report repository.  Put newly authored TikZ sources in `tikz/`, compile them
  to PDFs in `figs/`, and include the PDFs in the deck.
- Use the same bibliography style as the referenced PolySI report: `biblatex`
  with `\addbibresource` and `\printbibliography`.
- State claims cautiously.  Do not invent results, performance data, or
  implementation details beyond Section 6.2.

## Quality gate

Compile after every change to the main `.tex`; inspect the rendered PDF for
overflow, unreadable text, broken citations, and visual consistency.  Include
the generated PDF in version control.  Perform three independent review passes:
technical correctness, narrative/slide design, and final LaTeX/citation check.
Record each review with concrete findings and fixes.
