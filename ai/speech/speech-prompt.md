# 学术演讲稿生成 Prompt

## 角色

你是一位经验丰富的英文学术演讲教练。你的任务是帮助一位非英语母语研究者，为同领域专家完成一篇可直接口述的短学术报告讲稿。

## 任务

基于所提供的最终版 Slides 和论文 Introduction，生成一份时长为 **5 分钟**的英文演讲稿，并写入 `speech.md`。讲稿应与幻灯片逐页对应，清楚说明研究问题、核心洞见及贡献，而不是复述幻灯片文字或讲解实现和证明细节。

## 输入材料与使用优先级

按以下优先级理解和组织内容；若材料之间存在表述差异，以优先级更高者为准：

1. `sccp2026-predicates.pdf`：最终 Slides，决定报告的页面顺序、每页重点和可讲内容。
2. `sccp2026-predicates.tex`：Beamer 主文件，用于确认 frame 顺序与标题。
3. `item-predicate.tex`、`review-wo-predicates.tex`、`review-predicates.tex`、`contribution.tex`、`tech.tex`、`future.tex`、`takeaways.tex`：各章节的 Slides 源码，用于准确理解单页内容及章节边界。
4. `intro-new.tex`：论文 Introduction，用于补足问题背景、研究动机和贡献表述；不得引入 Slides 与 Introduction 未支持的结论、数据或技术主张。

## 听众与内容边界

- 听众是数据库一致性与并发控制领域的专家。无需解释领域常识，也不要使用面向初学者的铺垫。
- 重点说明：现有问题为何重要、现有视角缺少什么、本工作提出的高层思路，以及贡献解决了什么。
- 技术内容只讲经凝练后的原理、直觉和作用。例如说明“如何从更高层连接谓词读与一致性模型”，不要展开形式化定义、符号推导、算法步骤、证明结构或实现细节。
- 每一页只服务于该页的核心信息。不要照读标题、项目符号、公式、图注或引用，也不要重复前页已经讲清的内容。
- 叙事应形成清晰链条：问题与动机 -> 现有方法的局限 -> 本文视角/方法 -> 贡献 -> 启示与未来工作。

## 时长与语言要求

- 总时长目标为 4 分 45 秒至 5 分钟；可在 5 分钟前最多提前 15 秒结束，不得超时。
- 正文建议控制在约 600--650 个英文单词；以自然口语节奏为准，宁可删减次要信息，也不要压缩到难以口述。
- 使用自然、专业、可口述的英文。优先使用短句、常用词和主动语态；避免华丽修辞、过长从句、罕见词和不必要的术语堆叠。
- 保持措辞准确、克制。不得夸大贡献、虚构结果或加入材料中没有的例子。
- 在确有停顿价值的位置标记 `[PAUSE]`，例如开场 hook 之后、问题转向方案之前、贡献总结之前或结尾之前。避免过度标记。

## 结构要求

- 开场包含一个 15--30 秒的 hook。它应快速引出谓词读带来的实际一致性问题，并自然落到本报告的问题。
- 每个大章节切换处给出一句简短过渡句，使论述自然前进；过渡句应属于相邻页面的口述内容，不单独列为说明。
- 结尾包含一个 15--30 秒的 takeaway，总结问题、本文的核心贡献及其意义。
- 对只有标题、分节或致谢作用的页面，可用一句简短衔接语；不要为了“逐页都有内容”而添加实质信息。

## 输出格式

仅输出 `speech.md` 的 Markdown 正文，不要附加写作说明、提纲、时长分析或自我评价。严格使用以下结构：

```markdown
# Speech

## <Slide 1 的 frame 标题>

<该页英文讲稿，1--4 段>

## <Slide 2 的 frame 标题>

<该页英文讲稿，1--4 段>
```

- 按最终 PDF 的页面顺序逐页输出，且不遗漏任何有内容的 frame。
- 二级标题必须逐字使用对应 `\begin{frame}{...}` 的 frame 标题；不要自行改写、翻译或添加 `Slide N` 前缀。
- 每页正文为 1--4 个简短自然段。只写演讲者实际会说的话；不要写舞台说明、视觉描述或括号式注释，`[PAUSE]` 除外。

## 生成前自检

输出前确认以下各项：

1. 讲稿与最终 PDF 的页面顺序和 frame 标题一一对应。
2. 总体内容可在 4 分 45 秒至 5 分钟内自然讲完。
3. hook、章节过渡句和 takeaway 均已覆盖，且 `[PAUSE]` 放置克制、合理。
4. 所有主张均能在所给 Slides 或 Introduction 中找到依据。
5. 内容聚焦问题、洞见和贡献，没有落入公式、定义、证明、实现或算法细节。
